## core
Generate Dream 2 data from the user's intent: a prompt, sketch or existing revision.
Return one complete source file starting with dream 2; no markdown or explanation.
Include at least one object, asset, include, complete world or standalone scenario.
Use the command contract and only supported fields, contexts and constructors.
The engine owns rendering, physics and shaders. No JS, module code, URLs or callbacks.

If intent is unsupported, add unresolved id(label="specific unsupported intent");
in the full-world source. Do not fabricate syntax or silently claim unsupported physics.
Run node scripts/dream.mjs check file.dream. On failure read code, line, column,
path, message, expected. Repair the entire source, preserving unrelated IDs and
content. Only ok:true may be accepted; full worlds also pass scene playability.
Object-only use compileDream. World fragments use compileDreamWorld. Complete
playable worlds use compileDreamScene with host-owned identity/hash.

## objects
Syntax: kind id?(key=value,...); or kind id?(key=value,...){...}
IDs: lowercase [a-z][a-z0-9_]{0,31}; do not use sin, cos, true, false as IDs.
Use a unique ID for every top-level declaration and each named item in a block.
Use IDs for references; label="..." is display-only. Keep IDs stable on repair.
Use table field order. Always emit required fields. Use named constructor fields.
No aliases: rot_deg, heading_deg, spin(axis=z,deg_s=90),
swing(axis=z,deg=20,hz=.25,phase_deg=0), roll(axis=y,radius=8).
Colors are six-digit hex. material colors always contains two colors.
Material style may be toon, grain, glow, stripes, cloth, brick, wood or stone.
For brick, colors=[fired_face,mortar]; use a subdued warm gray for mortar, not
a second red. The engine supplies staggered 24x7.5 cm courses, thin recessed
joints and restrained brick variation. Do not model every brick or cut open
voxel slots to represent mortar. Wood colors=[base,grain_tint]; grain follows
each member's longest dimension. Stone colors=[base,mineral_tint] gives natural
mineral variation, not a block bond. These finishes keep physical pattern size
through placement scale, instancing and fracture. Detail is filtered below a
pixel; relief is visual only. No custom GLSL, texture URLs, roughness or bump
fields. Use voxels/fill/cut for actual openings and authored destruction chunks.

Coordinates: world [x,y] = right/down; object [x,y,z] = Y up; asset forward +X.
World heading 0=east, 90=south. rot_deg is local Euler XYZ in degrees.
Shapes use full bounding dimensions. Cylinders/capsules/cones point along Y;
torus holes point along Z. Motion axes are primitive-local: a cylinder with
rot_deg=[90,0,0] still rolls about its own Y axis; a torus wheel uses Z.
Prism parts require outline=[[x,y],...] with 3..24 simple polygon vertices in
0..1, spanning 0..1 on both axes, area >= .01. Either winding; no holes,
duplicate closing point, crossed/touching edges or zero-length edges. The
engine centers the outline in full size X/Y and extrudes through full size Z.
Use concave outlines for wheel openings and sloped outlines for cabins/panels.
Only prism parts accept outline; beams remain box/cylinder/capsule.
A contact needs radius OR size=[width,depth], never both. size permits a static
upright rectangle with optional heading_deg; radius remains a cylinder. Rectangles
use .1..128 sides and .1..160 height, cylinders use radius 1..64 and height 1..160.
No rectangle seats, moving routes or whole-object impacts. Interiors need the
interiors packet; do not invent floors by hiding a car under an ordinary roof.
Keep feet/bases at local Y=0. World placements take only XY, not arbitrary height.
Use endpoint beams for connected struts; start each fork inside its trunk.
Cylinder part/beam taper is optional, finite .1..1 (default 1): +Y/to diameter
divided by -Y/from diameter. width/depth/size remain full base dimensions.
Use taper for continuous trunks and branches; use groups for rigid transforms,
joints for connected articulation. Keep physical bodies separate from visual parts.
Within the 32-part limit, add identifying details such as window frames, wheel hubs,
forks, bark marks and food scores. Keep them attached to the same joint or fragment
as their support. Detail must not bridge independent break zones or close a doorway.
Use foundations for upright solid buildings, ground(mode=surface) for tilting props.
The cloth material is flag wind, not garment physics; use toon/grain for rigid clothing.
A joint never inherits primitive dimension scaling; scale a surrounding group.
roll(axis=...,radius=...) also works on joints: all children turn as one rigid
mechanism by traveled distance / resolved radius. Use one bearing frame for
an axle's tires, hubs and shaft, or a bicycle's chainring, arms and pedals.
The bearing stays fixed during visual body suspension travel. Orient bearings
so forward travel rolls their wheels forward; keep shafts inside the hubs.
Prop furnish templates bake roll joints at rest; controllable parking retains them for activation; swing/open joints remain
ineligible for furnishings unless explicitly baked with pose=rest. Live roll joints count toward existing jointed
assembly budgets. No controller scripts or independent part orbit callbacks.

Expressions: numbers, scoped constants, + - * /, sin(degrees), cos(degrees).
Global constants may forward-reference each other without cycles. Local constants
resolve in order. Components see globals and their explicit bindings, never caller-local names.
component chair(params=[height],materials=[paint]) declares numeric and material
parameters. use seat(component=chair,args=[24],materials=[oak]) binds both lists
positionally with exact arity. At most 8 unique names across both lists. Material
formals cannot shadow global numeric constants or numeric formals. Material actuals
resolve in the caller; callees see global materials plus only their own bindings.
Pass a parent material parameter explicitly to a nested use. No dynamic shaders,
string substitution, implicit material inheritance or changed identity semantics.
Use repeat id(index=i,count=...) for bounded variation; use explicit use-site IDs.

Budget per source: 65536 characters, 12000 lexer tokens, 2048 expanded statements,
16 objects, 16 nesting levels, 0..32 repeats, 8 numeric/material parameters combined per component. No recursion.
All numeric results finite, abs<=1000000. Combined positive scale<=16.
Per assembly: 1..32 parts, <=12 joints, joint depth<=4, assembled reach<=256.
Part size: each .1..128 in object DSL v2; legacy v1 retains .5..128. Beam endpoint length remains >=.5. Use thin parts for glazing, pipes and rails; bodies/contacts remain independent. Final offsets: X/Z -64..64, Y -128..128.
For every new object emit measure(kind=...,axis=...,meters=...) directly inside it.
10 canonical world units = 1 meter. This uniformly sizes assembled rest-pose
geometry AND all physical contacts, foundations, seats, wheels and fragments.
Keep local part dimensions inside the existing bounds; do not pre-scale them.
Profiles/axes/ranges are in contract.proportions.profiles. Examples:
car x 3.55; tree y 10; plane z 10.8; person y 1.75; bicycle x 1.8;
skateboard x .82; bench x 1.8; table x 2.4; bread: food x .35.
place.scale is 0.5..2 variation after measurement, still inside the kind's range.
Resolved scale must be .05..4. Use kind=custom for deliberate fantasy sizes.
In car worlds: tree height and plane span > player length; bike/board length < player length.
Never infer a proportion class from a label. Omit measure only for legacy assets.
Joint offsets: each -64..64. Body radius 4..30, height 4..160, friction .5..5.
Foundation size .5..128; only upright solids, no mobile objects/player.
Deform seed integer 0..65535, amount in [0,0.24]. One motion per part/joint.
Spin deg_s -171.88..171.88; roll radius 1..32.
Sway deg 0..6.87, hz .016.. .477. Swing deg 0..80.21, hz .016.. .636,
phase_deg -180..180. Open deg -180..180, radius 20..160.
At most 8 upright solid compound contacts: offset X/Z -64..64, Y 0..128,
radius 1..64, height 1..160. Contact geometry replaces the main body footprint.
rideable requires a solid body without foundation/impact. Seat Y 0..128.
Driver control requires a single cylinder without compound contacts; passenger-only seats may use compound contacts.
Add control=car|bicycle|skateboard|scooter|boat|plane for direct player control. These are
bounded engine profiles, not generated physics. Controlled vehicles start parked;
place at XY or use a route only for its initial pose/infrastructure. They do not
follow that route while being driven, and stay where the player leaves them.
Omit control for passenger seats on autonomous routes, including buses, trams and trains.
Give boats full-hull navigable water and a boarding point near dry shore; bridge travel requires hull/body clearance below the deck and side rails. Give planes a clear dry takeoff/landing area. Ground vehicles
share terrain/contact mechanics. F prefers clear dry ground, then allows wading/swimming
exits into water. No exit during flight. Boats and swimmers stay below bridge decks.
Walking climbs contact tops in steps up to 4 world units (40 cm) with headroom;
visual mesh details alone are not steps. Use explicit low contacts for terraces.
Space jumps on foot/bicycles/skateboards/scooters, hops boats, or speeds a swimming stroke.
Shift runs/swims faster. Bicycle steering/lean, boat inertia, jump buffering, water
support and aircraft climb/stall response belong to engine profiles, not DSL code.
Walking and non-racing vehicles preserve the original car's checkpoint progress.
Aircraft need takeoff speed; Space/Shift climbs/descends and flight blocks exit.
Water landings stall the aircraft at the surface; R recovers it to its start.
The engine supplies a standing Explorer and seated traveler from Dream assemblies;
model output still contains no controller code, input callbacks or physics scripts.
Steam only: rate_s 1..12, position X/Z -64..64, Y 0..128.


HUMANOID RIGS
Use joint(...,bone=...) for locomotion, not swing motions on straight stick limbs.
Exactly 12 unique bindings, measured decor person only. Parent tree:
root -> spine -> left_shoulder -> left_elbow; mirror right_shoulder/right_elbow.
root -> left_hip -> left_knee -> left_ankle; mirror right_hip/right_knee/right_ankle.
Rest frames unrotated, facing +X, +Y up, left +Z. root=[0,positive_height,0],
spine=[0,nonnegative_height,0], hip=[0,0,signed_width], shoulder=[0,positive_height,signed_width].
Elbow/knee/ankle=[0,-length,0], length >= .5. Root height >=1.
Every visual part belongs to a bone; overlap rounded joint caps at elbows/knees.
No independent part/bone motion, fragments or zones. Keep feet at Y=0 in assembled rest.
Engine owns walk/run blending, lifted steps, two-bone legs, jump/landing, crawl/tread,
reduced-motion poses and sports overrides. Body and movement physics stay separate.
No extra joints, generated controllers, skinning, or terrain foot probes. Existing
12-joint, depth-4, 32-part and 24-live-assembly caps unchanged. Furnish requires pose=rest for passive rigs or motion=walk(...) for shared ambient walkers.
Use examples/humanoid.dream as a complete template; keep binding names, vary geometry,
colors and measured size. Labels/generated IDs do not choose anatomy or behavior.

## world
For a full world emit exactly one world and one road, and 2..64 ordered checkpoints.
world size positive integers <=16384. Host supplies identity, source hash/provenance.
Player is an object ID with a solid body, no foundation/contacts/seat/emitter/impact/break zones.
Road: 6..64 cyclic anchors, adjacent distances>8, width 40..240. Keep its complete
width/curbs inside the world and leave conservative clearance around bends.
Checkpoints: at center, nonzero dir, width (0,240]; start is first. Put them on road.
Effects: simple polygons of 3..256 vertices, area>=1; kind=ice|boost; keep on road.
Hills: <=16, radius X/Y 120..1600, height 0..320. Tints <=16, radius 120..3000.
Bridge: <=8, span 80..600, width 64..240, arch 0..40, dry open ends.
Road corridor plus curbs must fit between rails across the entire span.
Timber owns the wooden driving deck; the engine clips asphalt and tapers curbs.
Water: <=8 combined basins/watercourses. Level 0..300, depth 2..24, bank 20..120,
flow components -60..60, drag .5..6; waves=[speed 20..100,damping .5..4,strength 0..2].
Water polygons: 3..32 points, simple, area 400..8000000, X/Y extent 80..16384;
contain banks and do not overlap other water. Each body is limited to 131072
wave cells: (ceil(X extent/24)+1)*(ceil(Y extent/24)+1). Extend water with connected
width-bearing stations rather than separate overlapping circles. Watercourses keep their default drag/waves; use only their listed fields.
Watercourse: 2..8 stations [x,y,width],
width 80..1200; distinct stations. ends=round default; ends=open removes caps. Put open ends at world boundaries.
Routes <=12: kind rail|path|water|air|ambient|street|tram|walk, mode loop|shuttle, vehicle speed 12..160, wait_s 0..12,
2..64 points (loop>=3), segments>=8, total length<=12000. Air requires altitude
60..300. Ambient optionally accepts altitude 60..300; omit it for ground movement.
Ambient speed .5..160. Use ambient for decor-only wildlife: no roads, rails, runway,
grass clearing, vehicle control, impacts, foundations or physical contacts.
It follows terrain + optional constant altitude, including the loop seam.
Ground habitat footprints must stay dry and clear of solids. Compose wings/legs with
existing bounded swing joints; use slower ground speed to match their gait.
Use custom measurements for animal length/wingspan; do not infer size from a label.
Path-only width 16..120 is the full corridor width. Use surface=trail|cycle|paved
only with an explicit width. New dedicated paths should declare both. Reserve their
full width plus at least 8 units from racing-road curbs, water, physical props,
other ground routes and runways; validation adds conservative sampling clearance.
Do not cover a path with road, or place trees/benches on its surface. Place boarding
stops beside approachable dry ground. Use generous route extents for world activities;
keep objects at their measured sizes. Omit width/surface only for legacy shared paths.
Widen bends to keep the inside ribbon from folding; avoid turns sharper than 120 degrees.
The engine does not invent crossings or reroute invalid layouts.
Place uses exactly one of at or route; offset 0..2048 only with route;
scale .5..2; heading_deg -360..360 only for at placements (routes own heading). <=64 placements; scene <=24 resident mobile actors including controllable vehicles,
<=24 live joint assemblies including the standing engine character; reserve one slot,
so source objects plus the player vehicle may use at most 23. <=24 resident impact objects, <=128 resident potential fragments; see interactions for pooled static destruction,
<=16 steam emitters. Vehicle route actors need solid bodies without foundation/impact; compound contacts are allowed only on street/tram/rail NPCs;
ambient route actors require decor bodies instead.
One driving height per XY. No stacked roads or ground driving under bridges. Boats use the water bed,
and may pass under a deck only with full hull/body clearance. Boat exits require
real dry shore; never place a boarding point underneath a deck.
Hollow buildings/tunnels use separated contacts and overhead clearance.

## interactions
DESTRUCTION EXTENSIONS
Bounce: knockable body; restitution in [0.1,0.9], lift in [0.05,0.8].
Break: solid body; speed 40..400, scatter 0..160, lift 0..180, spin 0..8,
lifetime 2..8. <=8 static fragments; fragment blocks cannot nest.
Whole-object impacts cannot have foundations, compound/offset contacts, seats or emitters.
One contact at [0,0,0] is allowed for break/topple; use it for a narrow pole while preserving body radius >=4. Topple uses that root body radius as its hinge envelope; it must clear the visual foot.
Prefer flat ground for scattering props; foundations cannot fill their downhill gaps.
Topple uses terrain-aware support and can fall on hills.

break(...,pattern=scatter|splinter|crumble) optionally chooses release motion.
Absent pattern preserves original scatter. Splinter throws wood parts forward;
crumble drops masonry near the contact with low lift, spin and rebound.
impact(mode=topple(speed=110,duration=1.1,lifetime=8)); topples the entire static
solid as one rigid fragment about the far edge of its body, away from impact.
If no part has fragment metadata, Dream 2 compiles all parts into one stable rigid fragment.
With explicit fragment blocks, all parts must belong to one group. duration .25..2; lifetime 2..8 and >=
duration+.8. Other whole-object impact restrictions still apply.
zone facade(at=[42,0,0],radius=16,height=39,mode=break(speed=135,scatter=55,
lift=45,spin=3,lifetime=7,pattern=crumble)){ visual statements }
Zone at is an object-local cylinder base; visual coordinates inside are relative
to it. radius 1..64, height 1..160, offsets X/Z +/-64 and Y 0..128. Only break
mode is allowed. A zone may use fragments/groups/components/static joints;
fragments cannot cross zones. Up to 4 zones and 8 total released fragments per
assembly; keep the 32-part, reach and scene budgets. Zone blocks belong directly
inside an object. They cannot nest or appear in visual components, but use sites
inside them can compose visual components. Every zone owns at least one part;
retain structural geometry outside all zones. The object must be an upright
solid without whole-object impact, a seat, emitter or animated geometry. Core
contacts and foundations are allowed and survive section damage. Author core
contacts separately so an intact root cylinder does not block the intended
opening after a zone breaks. Terrain foundations stay intact.

SHARED INTERACTION RULES

At most 16 rules, exactly one owner per category, in the entry file only. Loaded modules cannot declare rules. Apply across local/imported templates, placements and furnishing before object validation. A rule replaces local impact settings. A break rule replaces every existing break-zone impact when zones exist; retained core/foundations remain. Bodies, animation and fragment grouping must be compatible; incompatible assets fail compilation, never silently lose construction. Each placement has independent damage. Scene v1 interactionRules is optional for legacy data, defaults to []; serialized placements must match. Legacy scenes retain 24 reactive placements and 128 potential fragments; all templates retain <=8 fragments. Pooled worlds use the limits below; rules never bypass bounds. Select by measure.kind, never labels/position/randomness. custom is one catchall category, not separate bread/rock/ball types. Current live policies cover tables, benches and street lamps; other categories keep authored defaults. Existing break/topple/bounce constructors only, no scripts or structural/material simulation. Complete example: examples/interaction-rules.dream.

world(...,damage_pool=true) enables instanced static break/topple props across

Keep existing source/project/4096-placement bounds; at most 128 distinct pooled

## npcs
ACTOR OWNERSHIP AND NPC PROGRAMS
For every new general actor placement emit role=controllable or role=npc explicitly.
Use role=ambient only with the bounded population motion contract below.
role=prop is passive scenery; no route or behavior. Mechanical motion/destruction remain possible.
Template rideable.control is capability; place.role chooses ownership. controllable needs
that capability and starts parked, accepting player input after boarding. npc is engine-owned;
a driver-capable NPC cannot be boarded. Passenger-only NPC train seats remain usable.
Legacy omitted role infers control capability -> controllable, else route -> npc, else prop.
world.player remains the original car; no humanoid possession or generated input profiles.

 state walking(action=patrol){on notice(event=near_player,to=watching,radius=65);}
 state watching(action=idle,face=player){on leave(event=far_player,to=walking,radius=95);}
