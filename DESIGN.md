# Dreams Lab workspace

Mode: Operate. A first-time researcher should understand what is being tested,
what can change and what happened without reading Dream source or protocol data.

Keep Minimum Effort’s warm white, charcoal and yellow identity, local Manrope
body type and Archivo headings. Yellow marks a selection; it is never body text
on a light background. Controls use visible focus, native buttons and disclosures.

## The primary flow

The header states the Lab’s purpose in one sentence. The primary action is Run
experiment. Scenario buttons choose Delivery, Warehouse or Classroom. A readable
task and environment summary replaces the preset-only editable brief boxes.
Team size, Budget per agent and Time limit are the visible conditions. Stack all
three in one column, with labels above equal-width inputs and units aligned on
the right. Use the same structure on desktop and mobile. Explain simulation
steps once, without treating them as real seconds.

Advanced setup contains the random seed, host agent assignments, active controller
ownership and Dream rules. Code can be inspected or edited; Use scenario restores
the brief and preserves the manual draft. The header says Scripted agents in the
browser baseline; the saved host identifies its local workspace. No provider is
implied to be connected. The host’s built-in and test-connection controls retain
the original baseline/external-mock protocol values.

Save setup belongs to the conditions. Saved experiments, New experiment and Run
history are below setup. Comparison choices appear when there are two runs.
Updates preserve native button and checkbox identity and keyboard focus.

## Watching and understanding a run

The 3D world remains the central observation surface. Drag/scroll guidance is
visible, with keyboard camera controls on the focused view. Playback controls
appear after a run exists. A changed draft is labeled while the accepted world
continues to show its own source-pinned result. Host playback pause explicitly
says that execution continues on the local host.

Outcome copy leads with completion or the time limit, then coins spent and
simulation steps. It suggests the next useful action without inventing failure
causes or calling lower spend a better result. Agent activity is a disclosure.
Results breakdown leads with three aligned step charts: completed tasks, coins
spent and cumulative waiting agent steps. They share a step cursor and a compact
readout. Pointer hover and arrow keys inspect without pausing; click or Enter uses
the existing replay owner to seek. Home/End inspect first/latest, Escape restores
the playback cursor. New points extend the history without resetting inspection.
Use discrete step lines with visible zero-based scales, no smoothing, animation,
automatic diagnosis or new chart dependency. Derive new samples incrementally
from validated transitions. By agent holds task-progress bars and stacked time;
tables and events stay inside disclosures. Timeline CSV exports the exact history
with the run’s source pins and snapshot outcome.
Results remain available during execution. Their scope labels the latest committed
head; timeline readouts identify the inspected step. Per-agent charts and snapshot
exports stay at the head. Update chart values, table cells and download
snapshots in place; preserve disclosures, keyboard focus and scroll positions.
Event buttons open the attempted action and its recorded reason; Technical record
holds the raw observation/action/outcome. CSV exports the pinned measurements;
Full run (JSONL) preserves replay. Controller timing is a separate disclosure.

Comparisons lead with a measured difference. Different workloads show their own
completed/total counts; unfinished comparisons stay explicit. Three overlaid
step charts compare tasks, spending and waiting, using one actual step axis and
shared zero-based scales. First run is solid gold, second dashed blue; a compact
legend and matching readouts show their values and signed difference. Lines stop
at each recorded head; missing values remain missing. Inspection is read-only,
with one shared cursor, arrow/Home/End keys, click/Enter to hold and Latest/Escape
to follow again. Preserve held steps through live refresh. Timeline CSV exports
the aligned prefixes, differences and source pins. Run data
holds the full metric table, source hashes and saved revision pins. Evidence still
opens the exact run and step and leaves the editable draft intact.
Comparisons refresh while either selected run is executing, even when another
run is being viewed. Live refresh never scrolls the panel into view or changes
selection. Coalesce requests, reuse completed baselines, discard stale selections
and stop refresh timers on completion or disposal. Failed refreshes retain the
last snapshot with a short status message.

## Layout and accessibility

Desktop keeps a narrow setup column and a large world/result column. Each column
has one main vertical scroll area; expanded result tables do not create a stack
of nested scroll boxes. The shared desktop gutter is 24 pixels, mobile 16 pixels.
Narrow screens stack setup and world and keep Run experiment in a bottom action
bar, with space reserved below the content. Buttons and numeric inputs keep 40-pixel
control heights; playback controls do not shrink. Disclosure labels share the
content gutter, with chevrons aligned on the right and 40-pixel targets. Charts
and agent rows reflow to readable columns. Long titles use available header space.
Only table wrappers scroll horizontally and receive keyboard focus; surrounding
text, evidence and exports stay aligned. Comparison labels are left-aligned row
headers, numbers right-aligned under stable columns. Reduced motion, stale-result guards, accepted/draft separation,
one playback owner and renderer cleanup remain unchanged. No capture files are
retained with this pass.
