# Dreams Lab

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Researchers who want to define a world, context, scenario and task, run an AI
agent in that environment, change parameters and compare measured outcomes.

## Product Purpose

Muse interprets the research brief and proposes Dream source. The host validates
that source, executes supported rules and measures outcomes independently of the
agent. Researchers can inspect the generated source and replay a recorded run.

## Capabilities and Constraints

The user requested a fresh `dreams-lab/` folder at the repository root, selective
reuse of the existing Dream framework, and several interface variants for
approval before implementation. Workspace A is now approved. The user asked to
remove unnecessary interface text and repeated demo/illustrative notices.
This folder currently contains design previews.
Preview runs and metrics are illustrative. There are no model calls, physics,
evaluation or training results in these previews.

Later ports should share the canonical compiler and deterministic scenario
runner rather than fork Dream or import the complete city. Existing uncommitted
game work is outside this design slice.

## Brand Commitments

Use Minimum Effort's established identity: Manrope body type, Archivo headings,
warm white, charcoal and yellow. Keep the interface compact, readable and
keyboard accessible. Use concrete language and no invented performance claims.

## Open Decisions

The design chooser recorded Workspace as the initial selection. Real Muse
integration, first physical scenario, observation interface, inference budget and
experiment storage remain later decisions.
